## 0. 결론 요약

### 추천 출품 아이템
**생활 N빵 비서**: 가족·커플·룸메이트·여행 친구가 매일 반복하는 “누가 냈지?”, “얼마씩 내야 하지?”, “이번 주 장보기/집안일 누가 하지?”를 한 화면에서 정리하고, 토스 안에서 빠르게 공유할 수 있는 생활 정산/분담 미니앱.

### 왜 이 아이템인가
- 챌린지 주제와 직접 맞는다: 반복되는 귀찮은 계산·기록·생활 불편 해결.
- 토스 맥락과 맞는다: 돈, 정산, 생활비, 공유는 토스 사용자의 자연스러운 사용 맥락이다.
- 단순 리워드성 앱이 아니다: 실제 생활 문제 해결 기능이 있다.
- MVP가 작다: 수동 입력 + 자동 분배 + 공유 메시지 생성만으로도 제출 가능하다.
- 프로덕션 확장이 명확하다: 그룹, 반복비, 영수증 OCR, 정산 히스토리, 알림, 토스 로그인, 서버 동기화로 확장 가능하다.

### MVP 한 줄
“3분 안에 공동 생활비/집안일을 입력하고, 누가 얼마를 내면 되는지·이번 주 담당이 누구인지 공유 메시지로 끝낸다.”

### 프로덕션 한 줄
“생활 공동체의 돈·물건·집안일·반복비를 토스 안에서 가볍게 관리하는 공유 생활 운영 도구.”

- 주제: **“일상이 편해지는 순간”**
- 가이드: 반복되는 일을 자동화, 귀찮은 계산·기록 대행, 작은 생활 불편 해결, 생활 정보 한눈에 제공.
- 제외: 별도 핵심 기능 없는 단순 리워드성 미니앱, 주제 이탈 앱.
- 일정: 출품 2026-06-08 ~ 2026-06-30, 6월 30일까지 앱인토스 콘솔 첫 빌드 제출.
- 심사: 1차는 2026-07-01 ~ 2026-07-26 활성 유저 수(AU), 최종은 테마 적합성·사용자 경험 등 완성도 종합 평가.
- 노출: 7월 첫째 주 전용 테마 지면 및 큐레이션 지원.
- 상금: 1등 300만원, 2등 2명 각 150만원, 3등 5명 각 50만원.

출처: https://toss.im/apps-in-toss/blog/2606_vibecoding_challenge

### 1.2 앱인토스 플랫폼/기술 조사
공식 개발자센터 기준:
- 앱인토스는 토스 앱 내에서 서비스를 앱인앱 형태로 제공하는 플랫폼.
- WebView 방식은 CSR/SSG 웹 서비스를 미니앱으로 실행하는 방식이며, React/Vue/Svelte 등 기존 웹 개발 경험을 활용할 수 있다.
- 새 프로젝트는 `npx create-ait-app <app-name>`로 생성.
- 기본 설정 파일은 `granite.config.ts`이며 `appName`, `brand.displayName`, `brand.primaryColor`, `brand.icon`, `web.host`, `web.port`, `web.commands`, `permissions`, `outdir`를 정의한다.
- TDS WebView 사용 시 `@toss/tds-mobile`, `@toss/tds-mobile-ait`, `@emotion/react`, `react`, `react-dom`을 설치한다.
- 앱인토스 SDK: `@apps-in-toss/web-framework`.
- 로컬 저장소 API: `Storage.setItem/getItem/removeItem/clearItems`로 문자열 데이터 저장 가능.
- 공유 API: `share({ message })`로 네이티브 공유 시트 호출 가능.
- 딥링크: `intoss://{appName}`; 출시 테스트 QR은 `intoss-private://{appName}`.
- 빌드: `npm run build` 후 `.ait` 파일을 콘솔 업로드.
- 검수: 운영 검수, 기능 검수, 디자인 검수, 보안 검수. 평균 2~3일.
- SDK 2.x 마이그레이션 필수. 2026-03-23 이후 SDK 1.x 번들은 업로드 불가.
- 앱인토스 API 사용 시 파트너 서버와 앱인토스 서버 간 mTLS 인증서 설정 필요.

출처: https://developers-apps-in-toss.toss.im/llms.txt, https://developers-apps-in-toss.toss.im/llms-full.txt, 특히 `tutorials/webview.md`, `intro/onboarding-process.md`, `intro/guide.md`, 공유/저장소 API 문서.

### 1.3 정책/출시 리스크 조사
공식 서비스 오픈 정책 기준:
- 제한 서비스: 가상자산, 자금세탁 가능 서비스, 불법/부정 조장, 사행성/복권/베팅, 금융 상품 중개·판매·광고, 투자 자문, 의료 관련 직접 연결/예약/광고성 서비스 등.
- 자사 앱 설치 유도 및 외부 링크 이동 제한.
- 콘솔에 설정한 “앱 내 기능”은 미니앱 내에서 완결적으로 경험되어야 한다.
- 주요 기능이 외부 링크에 의존하면 반려 가능.
- 생성형 AI 결과 노출 시 사전 고지 등 별도 준수 필요.

출처: https://developers-apps-in-toss.toss.im/intro/guide.md

**본 아이템 정책 판단:**
- 금융 상품 중개가 아니라 생활비 계산/기록 도구이므로 상대적으로 안전하다.
- 실제 현금 교환/환불/충전 기능을 직접 제공하지 않는다.
- MVP에서는 송금 유도 버튼도 넣지 않고 “정산 결과 공유”까지만 제공해 자금세탁/금융상품 리스크를 피한다.
- 프로덕션에서도 결제/송금 연동은 후순위이며, 정책 확인 전까지 제외한다.

### 1.5 커뮤니티/생활 불편 가설
웹 커뮤니티 원문까지 충분히 안정적으로 수집하지 못했으므로, 이 문서의 커뮤니티 의견은 **확정 인용이 아닌 검증할 가설**로 둔다.

반복적으로 검증할 불편 가설:
1. 룸메이트/커플/가족 공동생활에서 “누가 냈는지”가 흩어진다.
2. 장보기·배달·관리비·구독료처럼 소액이 반복되면 정산이 뒤로 밀린다.
3. 카톡방에서 말로 정산하면 금액, 담당자, 완료 여부가 다시 묻히기 쉽다.
4. 집안일/공용물품 담당은 돈 문제와 함께 얽히지만 기존 정산 앱은 돈만 다룬다.
5. 여행 N빵 앱은 일회성에 강하고, 일상 반복비·담당 로테이션에는 약하다.

추가 검증 방법:
- 디시/더쿠/에브리타임/블라인드/네이버카페에서 `룸메이트 공용비`, `자취 집안일 분담`, `더치페이 정산`, `커플 생활비`, `공동생활비` 키워드로 실제 불편 문장 20개 수집.
- 수집 문장을 `정산`, `기록`, `책임소재`, `알림`, `갈등`, `반복비`, `장보기`로 코딩.
- MVP 카피와 기능 우선순위에 반영.

## 2. 제품 정의

### 2.1 문제
공동생활의 반복 잡무는 작지만 누적 피로가 크다.
- 돈: 누가 냈는지, 얼마씩 나눠야 하는지, 누가 아직 안 냈는지.
- 물건: 휴지/세제/생수/간식 같은 공용품을 누가 언제 사야 하는지.
- 일: 분리수거/청소/장보기/세탁 같은 담당을 누가 맡는지.
- 기록: 카톡·메모·영수증·계좌이체가 흩어져 재확인이 어렵다.

### 2.2 타깃 사용자
1. 20~30대 자취생/룸메이트
2. 커플/신혼부부의 생활비 분담 사용자
3. 친구끼리 여행·모임 비용을 정산하는 사용자
4. 가족 내 장보기/공용비를 관리하는 사용자
5. 회사 소규모 팀의 커피/간식/회식 사전 정산 사용자

### 2.3 핵심 가치 제안
- **계산 피로 제거:** 비용을 입력하면 자동으로 분배한다.
- **말 꺼내는 부담 감소:** 정산 요청을 자연스러운 공유 메시지로 만든다.
- **반복 관리:** 매번 새로 계산하지 않고 템플릿/반복비로 재사용한다.
- **돈+일 통합:** 비용 정산과 담당자 로테이션을 함께 본다.
- **토스 맥락:** 토스 안에서 짧게 열고, 저장하고, 공유한다.

### 2.4 제품 원칙
1. 첫 화면에서 5초 안에 용도를 이해해야 한다.
2. MVP에서는 로그인·서버·결제 없이도 핵심 가치가 작동해야 한다.
3. 공유는 강제 송금이 아니라 “정리된 메시지” 중심으로 한다.
4. 사용자 개인정보와 금융정보 수집을 최소화한다.
5. 토스 UI 문법: 한 화면 한 과업, 큰 CTA, 짧은 문장, 오류 원인+다음 행동.

## 3. 범위 분리

## 3.1 MVP급 PRD

### MVP 목표
6월 30일 전 첫 빌드 제출 가능한 수준. 심사 1차 AU를 위해 “누구나 바로 써볼 수 있고 공유할 수 있는” 기능에 집중한다.

### MVP 핵심 사용자 시나리오
1. 사용자가 미니앱에 들어온다.
2. “생활비 정산” 또는 “집안일 담당” 중 하나를 고른다.
3. 참여자 이름을 입력한다.
4. 비용/항목/담당을 입력한다.
5. 앱이 자동으로 정산 금액 또는 이번 주 담당을 계산한다.
6. 결과를 저장하거나 공유한다.

### MVP 기능 요구사항

#### F1. 빠른 정산 만들기
- 참여자 2~8명 입력.
- 비용 항목 추가: 항목명, 금액, 결제자, 나눌 사람.
- 균등 분배 기본값.
- 일부 참여자 제외 가능.
- 결과: 사람별 받을/보낼 금액 요약.

#### F2. 생활 루틴 담당 정하기
- 루틴 항목: 분리수거, 청소, 장보기, 설거지, 빨래 등 프리셋.
- 참여자 기준 라운드로빈 배정.
- 이번 주 담당 보기.
- 다음 주로 넘기기.

#### F3. 공용품 체크리스트
- 휴지, 물, 세제, 샴푸, 쓰레기봉투 등 프리셋.
- 수량/상태: 충분함, 곧 필요, 구매 필요.
- 구매 담당자 지정.
- 정산 항목으로 전환 가능.

#### F4. 공유 메시지 생성
- 앱인토스 `share({ message })` 사용.
- 메시지 예시:
  ```text
  이번 주 생활 N빵 정리
  - 민수 → 지연 12,500원
  - 현우 → 지연 8,000원
  - 분리수거: 현우
  - 장보기: 민수
  ```
- 외부 링크 의존 없이 텍스트 공유만 제공.

#### F5. 로컬 저장
- 앱인토스 `Storage.setItem/getItem` 사용.
- 최근 그룹 3개, 최근 정산 10개 저장.
- 개인정보 최소화: 이름/항목/금액만 저장. 연락처/계좌번호 저장 금지.

#### F6. 기본 상태/오류 처리
- 빈 상태: “아직 정산이 없어요. 첫 항목을 추가해볼까요?”
- 금액 오류: “금액은 1원 이상으로 입력해 주세요.”
- 참여자 오류: “정산하려면 참여자가 2명 이상 필요해요.”
- 공유 실패: “공유가 취소됐어요. 결과는 저장돼 있어요.”

### MVP 비기능 요구사항
- 모바일 WebView 기준 360~430px 폭에서 안정적으로 표시.
- 첫 로딩 2초 이내 목표.
- 모든 주요 CTA 터치 영역 44px 이상.
- 스크린리더용 버튼 레이블 제공.
- 색상만으로 상태 구분 금지.
- 외부 서버 없이 동작 가능해야 한다.

### MVP 기술스택
- Runtime: Apps in Toss WebView
- Scaffolding: `npx create-ait-app life-split-assistant`
- Framework: React 18 + Vite + TypeScript
- SDK: `@apps-in-toss/web-framework`
- UI: `@toss/tds-mobile`, `@toss/tds-mobile-ait`, `@emotion/react`
- State: React state + 로컬 reducer
- Persistence: Apps in Toss Storage API
- Share: Apps in Toss share API
- Testing: Vitest 계산 로직 단위 테스트, Playwright 또는 브라우저 수동 QA, 샌드박스 앱 실기기 테스트
- Build: `npm run build` → `.ait` 업로드

### MVP 제외 범위
- 토스 로그인
- 서버 동기화
- 실시간 그룹 협업
- 송금/결제/계좌 연동
- 영수증 OCR
- 연락처 권한
- 푸시/기능성 메시지
- 생성형 AI 추천
- 인앱 광고/수익화

### MVP 성공지표
- 첫 화면 CTA 클릭률 60% 이상.
- 정산 결과 화면 도달률 40% 이상.
- 공유 버튼 클릭률 20% 이상.
- 재방문율: 노출 기간 내 10% 이상 목표.
- 1차 심사용 AU 확보: 전용 테마 지면 노출 시 “공유→재진입”이 발생해야 함.

## 3.2 프로덕션급 PRD

### 프로덕션 목표
단순 계산기를 넘어 반복 사용 가능한 생활 운영 미니앱으로 확장한다. 다만 앱인토스 정책상 금융상품/송금 직접 연동 리스크가 있으므로, 결제·송금은 정책 확인 후 별도 단계로 둔다.

### 프로덕션 기능 요구사항

#### P1. 그룹 기반 생활공간

#### P2. 반복비 관리

- 반복 주기: 매주/매월/사용자 지정.
- 결제 예정일과 담당자.
- “이번 달 아직 정리 안 된 항목” 표시.

#### P3. 정산 엔진 고도화

#### P4. 집안일/공용품 운영
- 담당 로테이션 규칙: 순환, 랜덤, 고정, 지난 담당 제외.
- 담당 미완료 체크.
- 공용품 부족 알림.

#### P5. 영수증/사진 입력
- 영수증 이미지 업로드.
- OCR로 항목/금액 후보 추출.
- 사용자가 직접 확인 후 반영.
- MVP 이후 정책/개인정보 검토 필요.

#### P6. 로그인/서버 동기화
- 토스 로그인 또는 앱인토스 식별키 사용 검토.
- 파트너 서버 구축 시 mTLS 인증서 필요.
- 서버에는 최소 데이터만 저장.
- 탈퇴/삭제/보관기간 정책 제공.

#### P7. 알림/리마인더
- 정산 미완료 리마인더.
- 반복비 예정 알림.
- 담당일 알림.
- 기능성 메시지는 토스 로그인/정책 확인 후 적용.

#### P8. 신뢰/운영 기능
- 개인정보처리방침.
- 서비스 이용약관.

## 6. 계산 로직

### 6.1 MVP 정산 알고리즘
1. 각 비용 항목별로 `amount / splitAmong.length`를 계산한다.
2. 각 참여자별 net balance를 만든다.
   - 낸 사람: `+amount`
   - 나눌 사람: `-share`
3. 양수는 받을 사람, 음수는 보낼 사람.
4. 보낼 사람과 받을 사람을 매칭해 최소 거래 목록을 생성한다.
5. 원 단위 반올림 오차는 마지막 참여자에게 보정한다.

### 6.2 테스트 케이스
- 2명, 10,000원, 1명이 결제 → 5,000원 이동.
- 3명, 10,000원 → 원 단위 보정 포함.
- 한 항목에서 일부 참여자 제외.
- 결제자가 여러 명인 여러 항목.
- 금액 0원/음수 입력 방지.
- 참여자 1명일 때 정산 불가.
