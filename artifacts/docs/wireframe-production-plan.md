# 오늘 뭐 챙기지? 와이어프레임 제작 플랜

**작성일:** 2026-06-07 KST  
**기준 PRD:** `docs/prd-today-what-to-bring-mvp-production.md`  
**커뮤니티 조사:** `docs/community-painpoints-research.md`  
**목표:** PRD의 MVP 범위를 넘기지 않으면서 Toss Mini App 제출용 구현자가 바로 화면을 만들 수 있는 와이어프레임과 화면별 상태 정의를 만든다.

---

## 1. 제작 원칙

1. **PRD 고정 범위 준수**
   - 홈 검색
   - 홈 보기 모드: `준비 흐름별`, `카테고리별`
   - 그룹별 루틴 카드 목록
   - 그룹 내부 카드 순서 변경
   - 최근 사용 루틴
   - 체크리스트 바텀시트
   - 체크박스 기반 항목 체크
   - 커스텀 항목 추가/삭제/순서 변경
   - 기본값에서 제공하는 준비물 보기
   - 체크만 지우기 / 기본값으로 돌리기
   - 저장된 변경값 모두 삭제 안내/설정

2. **MVP 제외 범위 금지**
   - 로그인, 서버 동기화, 푸시 알림, 날씨 API, AI 추천, 의료 추천, 리워드, 결제, 광고는 와이어프레임에 넣지 않는다.

3. **Toss WebView 기준**
   - 모바일 세로 화면 기준: 360×640 ~ 420×740
   - 기본 NavigationBar와 Safe Area를 고려한다.
   - 한 화면 한 과업 원칙을 지킨다.
   - CTA는 해요체와 다음 행동이 분명한 문구로 쓴다.

4. **복잡도 제어**
   - 카드 순서 변경은 드래그 전제로 그리지 않고, MVP 구현 가능한 `위로/아래로` 또는 `순서 바꾸기` 편집 모드로 설계한다.
   - 기본 항목 삭제는 MVP에서 불가. 삭제 UI는 커스텀 항목에만 보여준다.
   - 체크 상태는 세션 상태로만 다루고, 저장되는 것처럼 보이지 않게 한다.

## 3. 화면 범위

## S0. 앱 진입 / 홈 기본 상태

**목적:** 사용자가 “오늘 뭐 챙기지?”의 가치를 5초 안에 이해하고 루틴 카드로 진입한다.

**포함 요소:**
- Safe Area 상단 여백
- 타이틀: `오늘 뭐 챙기지?`
- 서브타이틀: `오늘 나갈 때도, 내일 떠날 때도 빠뜨리지 않게`
- 최근 사용 루틴 섹션
- 검색창: `어떤 준비를 찾고 있나요?`
- 홈 보기 모드 segmented control: `준비 흐름별`, `카테고리별`
- 선택된 보기 모드의 그룹 목록
- 루틴 카드
- 하단 최소 설정/안내 진입

**기본 보기:** `준비 흐름별`

---

## S1. 준비 흐름별 홈

**그룹:**
1. `지금`
   - 출근
   - 외출
   - 운동
2. `오늘·내일`
   - 비 오는 날
   - 병원
   - 퇴근길 장보기
   - 아이 등원/등교
   - 출장/외근
3. `미리`
   - 골프
   - 캠핑
   - 국내여행
   - 해외여행
   - 등산

**와이어프레임 포인트:**
- 그룹명은 준비물 항목처럼 보이지 않게 섹션 라벨로 표현한다.
- 아래로 갈수록 더 미리 준비할 루틴이라는 흐름이 보여야 한다.
- 루틴 카드에는 제목 + 짧은 힌트 카피 + 진행/최근 여부 정도만 둔다.

---

## S2. 카테고리별 홈

**그룹:**
1. 일상/외출
2. 건강/운동
3. 가족/생활
4. 업무/출장
5. 레저/여행

**와이어프레임 포인트:**
- 준비 흐름별과 동일한 카드 컴포넌트를 재사용한다.
- 보기 모드가 바뀌어도 최근 루틴 섹션은 별도로 유지한다.
- 카테고리별에서도 그룹 내부 순서 변경이 가능해야 한다.

---

## S3. 홈 검색 상태

**상태:**
1. 검색 focus
2. 검색 결과 있음
3. 검색 결과 없음
4. 검색어 지우기

**검색 기준:** 카드명, 카테고리명, 태그

**카피:**
- placeholder: `어떤 준비를 찾고 있나요?`
- 빈 결과: `아직 맞는 루틴이 없어요. 직접 항목을 추가해 볼까요?`

**주의:**
- 검색어 원문은 저장/Analytics payload에 넣지 않는다는 구현 메모를 spec에 남긴다.

---

## S4. 최근 사용 루틴 상태

**상태:**
1. 최근 사용 없음
2. 최근 사용 1개
3. 최근 사용 2~3개

**카피:**
- 섹션명: `최근에 쓴 루틴`
- 빈 상태: `최근 쓴 루틴이 여기에 보여요`

**주의:**
- 최근 사용 루틴은 메인 카드 목록의 정렬을 바꾸지 않는다.

---

## S5. 그룹 내부 카드 순서 변경

**진입:** 홈의 `순서 바꾸기`

**상태:**
1. 편집 모드 진입
2. 카드 위/아래 이동
3. 첫 카드 위 이동 disabled
4. 마지막 카드 아래 이동 disabled
5. `카드 순서 초기화`
6. 편집 완료

**MVP UI:**
- 드래그 대신 `위로`, `아래로` 버튼 우선
- 버튼 접근성 label 예: `골프 카드를 위로 이동`

---

## S6. 체크리스트 바텀시트 기본 상태

**진입:** 홈 카드 또는 검색 결과 카드 탭

**포함 요소:**
- 루틴 제목
- 완료 상태/진행률: `7개 중 4개 완료`
- progress bar
- 기본 준비물 체크리스트
- 커스텀 항목 목록
- 항목 추가 입력
- `기본값에서 제공하는 준비물 보기`
- `체크만 지우기`
- 사용자 변경값이 있을 때만 `기본값으로 돌리기`
- 닫기

**높이:**
- 최초 70~80%
- 필요 시 전체 확장 가능

**뒤로가기 우선순위:**
1. 검색 입력 focus 해제
2. 열린 바텀시트 닫기
3. 홈에서 미니앱 기본 뒤로가기/닫기

---

## S7. 체크리스트 바텀시트 상태 변화

**상태:**
1. 체크 전
2. 일부 체크
3. 전체 완료
4. 체크만 지우기 완료
5. 기본값으로 돌리기 확인
6. 기본값 복원 완료

**카피:**
- 전체 완료: `다 챙겼어요. 이제 나가도 좋아요.`
- 일부 완료: `아직 2개 남았어요.`
- 체크만 지우기: `체크를 모두 지웠어요.`
- 기본값 복원: `기본 준비물로 되돌렸어요.`

---

## S8. 커스텀 항목 추가/삭제/순서 변경

**상태:**
1. 항목 입력 전
2. 빈 값 입력 방지
3. 중복 항목 안내
4. 항목 추가 성공
5. 커스텀 항목 삭제
6. 커스텀 항목 위/아래 이동

**규칙:**
- 기본 항목은 삭제 불가
- 삭제 버튼은 커스텀 항목에만 노출
- 기본 항목과 커스텀 항목의 완전 통합 정렬은 MVP 제외

---

## S9. 기본값에서 제공하는 준비물 보기

**목적:** 사용자가 원본 템플릿을 확인하되, 현재 사용자 변경값을 덮어쓰지 않는다.

**상태:**
- 읽기 전용 목록
- 닫기/돌아가기

**주의:**
- 이 화면/모달은 조회용이다. 복원은 별도 `기본값으로 돌리기`에서만 한다.

---

## S10. 저장/설정/초기화 안내

**포함 요소:**
- 로컬 저장 안내: `입력한 준비물은 이 기기의 앱 저장소에 저장돼요.`
- `홈 보기 기본값으로 돌리기`
- `카드 순서 초기화`
- `저장된 변경값 모두 삭제`

**주의:**
- `저장된 변경값 모두 삭제`는 확인 후 실행되는 위험 액션으로 표시한다.

---

## S11. 오류/빈 상태

**필수 상태:**
- 검색 결과 없음
- 최근 사용 없음
- Storage 불러오기 실패
- Storage 저장 실패
- 템플릿 데이터 fallback

**카피:**
- Storage 불러오기 실패: `저장된 변경값을 불러오지 못했어요. 기본 준비물로 보여드릴게요.`
- Storage 저장 실패: `변경사항을 저장하지 못했어요. 잠시 후 다시 시도해 주세요.`

## 4. 루틴 카드 카피 초안

| 카드 | 홈 카드 힌트 |
|---|---|
| 출근 | `사원증, 충전기, 우산까지` |
| 외출 | `집 키, 카드, 보조배터리까지` |
| 운동 | `수건이랑 이어폰 챙겼나요?` |
| 비 오는 날 | `우산만 챙기면 끝이 아닐 수도 있어요` |
| 병원 | `신분증부터 복용 중인 약까지` |
| 퇴근길 장보기 | `저녁 재료와 생필품을 한 번 더` |
| 아이 등원/등교 | `물병, 알림장, 여벌옷까지` |
| 출장/외근 | `충전기와 발표자료, 나가기 전에 한 번 더` |
| 골프 | `장갑, 볼마커, 티오프 시간까지` |
| 캠핑 | `랜턴 배터리와 연료처럼 작은 걸 놓치지 않게` |
| 국내여행 | `숙소, 교통편, 충전기까지` |
| 해외여행 | `여권, eSIM, 멀티어댑터까지` |
| 등산 | `물, 간식, 바람막이까지` |

## 5. 제작 순서

### Step 1. PRD 기준 화면 목록 잠금

**작업:** 이 문서의 S0~S11 화면 범위를 기준으로 와이어프레임 화면 목록을 확정한다.

**검증:**
- PRD MVP 기능 F1~F8이 최소 한 화면/상태에 매핑되어 있어야 한다.
- MVP 제외 범위가 화면에 포함되지 않아야 한다.

---

### Step 2. 텍스트 기반 wireframe spec 작성

**산출물:** `docs/wireframes/today-what-to-bring-wireframe-spec.md`

**포함:**
- 화면별 목적
- 사용자가 보는 요소
- 상태 변화
- CTA 문구
- 관련 PRD 요구사항
- 관련 Analytics 이벤트
- 접근성 체크

**검증:**
- `select_routine`, `view_bottom_sheet`, `check_item`, `search_routine`, `add_custom_item`, `reset_to_default`, `view_default_items`, `reorder_card`, `complete_routine` 이벤트가 화면 흐름에 매핑되어야 한다.

---

### Step 3. 정적 HTML 와이어프레임 제작

**산출물:** `docs/wireframes/today-what-to-bring-wireframe.html`

**방식:**
- 단일 HTML 파일
- 외부 빌드 의존성 없음
- 390px 모바일 프레임 중심
- 실제 앱 구현이 아니라 화면 구조 검토용
- PRD 색상 후보를 반영하되 low-fi 수준 유지

**검증:**
- 브라우저에서 열었을 때 홈, 검색, 보기 모드, 바텀시트, 편집 상태를 한 파일에서 확인할 수 있어야 한다.
- Safe Area/NavigationBar 영역을 시각적으로 표시한다.

---

### Step 4. PRD 대비 리뷰

**산출물:** `docs/wireframes/today-what-to-bring-wireframe-review.md`

**리뷰 기준:**
1. PRD 누락 여부
2. MVP 초과 여부
3. Toss UX 정책 리스크
4. 구현 난이도 리스크
5. 접근성 리스크
6. 카피 명확성

**검증:**
- 리뷰 결과에서 `반영`, `보류`, `추후` 결정을 분리한다.

---

### Step 5. 최종 와이어프레임 잠금

**작업:** 리뷰 반영 후 spec/html을 한 번 패치한다.

**잠금 기준:**
- 구현자가 PRD와 wireframe spec만 보고 MVP 화면 구조를 만들 수 있다.
- 화면에 포함된 기능이 PRD의 MVP 범위를 넘지 않는다.
- 바텀시트/뒤로가기/검색/순서변경/초기화 범위가 모호하지 않다.

---

## 6. 구현 인계 기준

와이어프레임 Gate가 끝나면 구현 플랜은 아래 순서로 분리한다.

1. Apps in Toss 템플릿 생성과 빌드 확인
2. 템플릿 데이터/타입/검색/reducer/storage/analytics 단위 구현
3. 홈 UI 구현
4. 바텀시트 UI 구현
5. 순서 변경/커스텀 항목 구현
6. QA/빌드/`.ait` 제출 준비

와이어프레임 단계에서는 실제 앱 코드를 만들지 않는다. 단, HTML 와이어프레임은 화면 합의용 artifact로 제작한다.
